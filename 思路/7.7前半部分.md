### 二、核心架构

*   **独立的 SubState (IntentClarificationState)**
    *   `original_query`: 用户的最初提问。
    *   `chat_history`: 存放 AI 的澄清问题和用户的补充回答。
    *   `is_clear`: **【核心开关】**意图是否已经足够清晰？(布尔值)
    *   `extracted_parameters`: 当 `is_clear` 为 True 时，输出的标准检索参数。
*   **Node A: `Evaluate_Intent` (意图评估节点 - LLM)**
    *   **动作**：大模型强制使用 `bind_tools` 机制。
    *   **状态更新逻辑**：
        *   调用 `ask_clarifying_question(question)` -> 写入问题到历史，设置 `is_clear = False`。
        *   调用 `submit_final_intent(keywords, entity)` -> 解析提取参数，设置 `is_clear = True`。
*   **Node B: `Ask_User` (询问用户节点 - HITL)**
    *   **动作**：使用 LangGraph 的 `interrupt()` 函数。程序在此完全挂起。
    *   **恢复**：收到前端数据后，将补充信息追加到 `chat_history` 中，并自动流转回 Node A。

# 检索

### 一、图

![image-20260707204943890](C:/Users/%E6%9D%8E%E4%BD%B3%E9%93%ADEric/AppData/Roaming/Typora/typora-user-images/image-20260707204943890.png)

### 二、核心架构

*   **独立的 SubState (SearchState)**
    *   `intent_params`: 接收来自上一层“意图子图”的结构化检索参数。
    *   `expanded_queries`: 存放 AI 生成的增强检索式（如同义词扩展、布尔逻辑组合）。
    *   `raw_papers`: 存放并行检索到的原始学术论文元数据与 PDF 路径。
    *   `raw_databases`: 存放并行检索到的开放数据库结构化源数据（JSON/CSV）。
    *   `raw_web_supplements`: 存放并行检索到的野外网页附件与补充材料。
    *   `citation_papers`: 存放通过挖掘种子论文的引用链（向前/向后引用）找到的额外文献。
    *   `deduplicated_assets`: **【最终输出】**经过全局去重与聚类后的高置信度数据源资产清单。

*   **Node A: `Expand_Query` (检索策略扩展节点 - LLM)**
    *   **动作**：大模型读取 `intent_params`，发散思维，生成同义词、上下位词，并构建出多套覆盖全面的布尔检索式（遵循 PPT 中“提高召回”的要求）。
    *   **状态更新逻辑**：将生成的策略写入 `expanded_queries`。

*   **Node B1-B3: 多库并发检索节点 (Parallel Search - Data Action)**
    *   **动作**：系统并发（Parallel）执行三路独立的 API 调用：
        *   `Paper_Search`: 调用 OpenAlex/预印本库等 API 检索文献。
        *   `Database_Search`: 针对性调用特定领域的标准开放数据接口。
        *   `Web_Search`: 限定 .edu / .gov 等权威域名，提取学术主页的补充材料。
    *   **状态更新逻辑**：分别将抓取到的初始资产写入 `raw_papers`、`raw_databases`、`raw_web_supplements`。

*   **Node C: `Citation_Expansion` (引用链扩展节点 - Data Action)**
    *   **动作**：针对 B1 检索出的一级优质论文（种子论文），通过 API 顺藤摸瓜，提取其引用的文献和被引用的记录，极大拓宽数据边界。
    *   **状态更新逻辑**：将挖掘出的补充文献写入 `citation_papers`。

*   **Node D: `Deduplicate_and_Cluster` (去重与聚类节点 - Logic)**
    *   **动作**：将所有 raw 池子和引用池子里的数据进行全局盘点。基于 DOI、文章标题、内容相似度进行多源合并去重；保留最权威的出处。
    *   **状态更新逻辑**：清洗完毕后，将干净的最优列表写入 `deduplicated_assets`，完成当前子图任务并向主图放行。

# 提取

### 一、图

![image-20260707204958214](C:/Users/%E6%9D%8E%E4%BD%B3%E9%93%ADEric/AppData/Roaming/Typora/typora-user-images/image-20260707204958214.png)

### 二、核心架构

*   **独立的 SubState (ParseAndValidateState)**
    *   `raw_assets`: 接收来自检索子图的多源异构数据列表（PDF、HTML、API 响应）。
    *   `standardized_blocks`: 经格式转换后，附带全局唯一标识符及溯源坐标（Bbox / XPath）的 Markdown 数据块集合。
    *   `filtered_blocks`: 经相关性过滤后保留的高召回率子集。
    *   `extracted_draft`: 提取智能体输出的结构化数据草稿。
    *   `validation_feedback`: 存放提取值与原文溯源坐标不匹配时的纠错指令，默认值为 `None`。
    *   `grounded_data`: **【最终输出】** 经严格保真验证，并绑定了物理溯源信息的结构化数据字典。

*   **Node A: `Format_Standardization` (格式标准化节点 - Data Action)**
    *   **动作**：执行异构数据的统一化处理。PDF 文件调用版面分析模型提取文本与坐标；网页数据通过 DOM 树解析剥离冗余节点，转换为包含 XPath 及图片链接的 Markdown 格式；开放数据库资源转换为标准 JSON。
    *   **状态更新**：输出 `standardized_blocks`。

*   **Node B: `Relevance_Filtering` (相关性过滤节点 - Data Action)**
    *   **动作**：利用轻量级向量检索与词频统计算法（如 BM25），结合全局意图参数，对 `standardized_blocks` 进行语义粗筛，剔除无包含目标实体或数值属性的冗余段落。
    *   **状态更新**：输出 `filtered_blocks`。

*   **Node C: `Data_Extraction_Agent` (目标数据提取节点 - LLM/VLM)**
    *   **动作**：作为执行智能体（Extractor），基于预定义的 Schema 对 `filtered_blocks` 实施强约束抽取。若遇到图表数据，则激活视觉语言模型处理。要求对不存在明确数据的情况返回 Null 以抑制幻觉。若接收到 `validation_feedback`，则基于错误日志调整提取策略。
    *   **状态更新**：输出 `extracted_draft`。

*   **Node D: `Fidelity_Validation_Agent` (忠实度校验节点 - LLM)**
    *   **动作**：作为独立的监督智能体（Validator），仅执行单一维度的验证任务：**信息保真度检查**。该节点将 `extracted_draft` 中的数值与对应的原始数据块进行严格交叉比对，判定提取结果是否完全来源于给定文本/坐标，禁止在此阶段进行跨文献的数据冲突分析。
    *   **状态更新**：若发生数值捏造或坐标错位，写入 `validation_feedback` 并触发循环重试；若验证无误，进入装配环节。

*   **Node F: `Bind_Provenance_Metadata` (溯源元数据绑定节点 - Data Action)**
    *   **动作**：将验证通过的结构化数据与对应的 Bbox 坐标、页码或网页 XPath 路径进行最终封装，确保输出数据具备完整的可追溯性。
    *   **状态更新**：将封装结果写入 `grounded_data`，传递至下游。
