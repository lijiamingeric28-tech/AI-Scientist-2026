# 加载速度与数据流转精简设计

用户要求继续编写性能方案，主要目标改为加载速度，清理不必要的数据流转。本轮交付设计和实施计划，方案编写过程中不改动产品代码。此前“项目本身”的范围保持不变。

## 目标和边界

- 优化首页、设置工作台、任务对话、数据结果、详情及历史回放的首次可用时间、切换速度和筛选响应。
- 减少无关字段、隐式全量下载、重复请求、重复 JSON 解码、重复展示投影和无变化刷新；保留合理热点缓存。
- 保留现有设计、系统配色、字体、操作入口、开发热更新，以及搜索、筛选、分页和选中对象的视图记忆。
- 规范包、原始资料、冻结版本、科学资格、原值和误差、失败原因、历史交付及导出内容保持原有语义。数据流精简不表示删除存储的数据。
- 本轮不开展科学库存储格式迁移、内存重构、模型/科学算法替换、IDE 索引治理或减少科学审核步骤。

## 设计选择

采用“先精简传输，再复用投影，再实现真正分页”的顺序。仅加压缩不能减少前后端解析和构造；仅缩小缓存可能增加等待；绕过校验会改变系统正确性，均不作为本轮主方案。

1. 摘要、目录、完整编辑数据使用明确的读投影。默认旧接口行为兼容，新前端请求轻量投影。
2. 按页面维护必要资源依赖；单项详情按精确ID读取。完整内容从详情、审计和显式导出入口访问。
3. 对话用一个一致游标的组合读模型；展示投影按事件游标复用并增量推进。命令资格仍由服务器重新校验。
4. 大结果通过不可变交付版本的派生读索引提供服务端搜索、排序和分页。索引属于可重建缓存，不改写原交付。
5. 请求合并、缓存失效、修订检查和取消行为统一，避免通过缓存引入旧版本覆盖。

补充契约：预览v2令牌基于全部可见内容依赖，而不是任务修订/日志游标；旧预览令牌行为兼容。服务端筛选导出明确采用新增`filtered`选择模式，复用列表过滤器并支持排除勾选，保留原有只导出当前交付修订的限制。

## 验收原则

- 先记录相同输入、相近外部负载下的基线，再比较请求数、未压缩字节、服务端构造时间和浏览器首次可用时间。
- 以当前真实数据和5000条合成性质/测量验证首屏和分页。冷/暖、Vite开发/生产构建、首次索引构建/已有索引分别报告。
- 功能对照覆盖未提供值、不可转换原值、长公式、质量标记、全部筛选结果导出、跨页选择、多窗口修订、历史回放和缓存损坏。
- 新路径失败时保留正确的旧读路径或明确错误；不能用空结果冒充成功，也不能让浏览器默默读错版本。
