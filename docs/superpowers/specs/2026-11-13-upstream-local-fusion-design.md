# 远端协作与本地知识工作台融合设计

## 用户目标与边界

保留同学线上版本的后端行为和前端功能，按本地现有设计系统美化其新增展示；完整保留本地知识库、性质规范工作台、自定义性质在科研链路中的执行、历史版本隔离及加载优化。用户已明确要求“开始融合”，本轮按此授权实施，本地验证完成后回写当前工作区，不向远端推送。

当前本地 HEAD 为 `46dd916`，远端 `origin/main` 已获取到 `3057b71`，共同基线 `abefdce`。本地基线后 10 次提交，远端 5 次提交；本地另有 172 个实际修改/新增路径。远端两次追问提交已以不同提交 ID 出现在本地，不能把同一套功能重复接入。

## 融合方式

采用以共同基线为依据的三方语义融合。单纯覆盖远端会丢知识工作台，单纯覆盖本地会丢资料工作台与科研后端增强；本次不采用任一方向的整文件偏好。

在当前分支和真实运行数据不变的情况下，用独立 Git 索引生成本地恢复快照，通过 `merge-tree` 生成暂存树，在普通暂存目录中处理冲突和验证，不创建或切换 Git 工作树。恢复点已固定为 `refs/codex/snapshots/fusion-20261113-local`，包含未提交文件；另保存原始补丁、索引及一致的 SQLite 备份。

## 界面设计约束

复用森林绿/学术风格对应的语义变量和五色调色盘，不在新增界面写独立色板。保留字体、8/12/16/20px 圆角、细边框、轻阴影、胶囊搜索与按钮、约 180ms 反馈及减少动态效果设置。弹层与抽屉复用本地模糊遮罩、焦点限制和关闭动效。

输入舱继续呈现为：`＋ / 查询选项 ｜ 输入天体或追问内容                     发送 / 停止`；当前选择内容和检索偏好在原有辅助区域展示，不删减远端功能。资料工作台和导出设置采用现有工具栏、标签、卡片、表格和弹层层级。

## 兼容及安全约束

- `record_list` 的本地第二位置参数为质量报告，远端为测量 ID；必须用明确的关键字接口同时支持，检查所有调用者。
- 旧交付 ID 读取、同交付历史修订、回答时点的记录/资料缓存及选择集合均按精确身份隔离。
- 索引包含新增原值坐标、质量和资料字段；索引协议随投影语义变化升级，命令不信任展示缓存。
- 主数据库、用户知识覆盖层、已发布规范包、原始 PDF 和历史报告不迁移或覆盖；所有写入回归使用隔离目录。
- 新增依赖按实际锁文件差异处理，不为了合并无条件升级整套依赖。

4. 实际浏览首页输入舱、追问、资料工作台、导出、知识与规范工作台；明暗主题及自定义调色逻辑保持一致，桌面横屏不溢出。
