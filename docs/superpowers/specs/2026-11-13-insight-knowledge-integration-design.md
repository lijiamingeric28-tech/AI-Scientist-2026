# 新版科研工作台洞察与知识依据衔接方案

状态：核查完成，推荐方案待确认，尚未实施。本轮按用户要求停止性能优化，仅检查实际调用链、七份样例的已保存结果和当前接口，并提出衔接方案。未调用模型、未改生产代码或历史数据。

## 一 已核实的事实

**整个后端仍有洞察阶段；新版样例也确实向资料总结提供了知识背景。缺失的是旧模式的性质级综合洞察，以及新版界面中明确可查的知识依据。**

| 项目 | 旧六份样例 | 最新 SN 2014J 样例 |
|---|---|---|
| 固定策略 | `research-property/1` | `material-summary/1` |
| 最终保存报告 | `InsightReport/4` | `MaterialSummaryReport/1` |
| 主要组织方式 | 按性质汇集多个来源的结果并解释 | 按资料与性质组合介绍该资料 |
| 已保存结果 | 共 18 张性质卡片、63 个知识块引用位置，六份均 complete | 67 条 ready 的“资料×性质”总结，覆盖 39 个资料组；四项性质分别 16、19、17、15 条 |
| 知识调用 | 有，正式发布知识与理论背景 | 有，67 份总结均保存非空 `basis.knowledge` |
| 知识计数 | 各报告保存的块，不当作跨任务去重数量 | 3 个不同条目，共 86 次输入引用；重复使用不等于新增条目 |
| 性质级综合卡片 | 有 | 没有，保存记录中无性质洞察计划和检查点 |

最新样例准确 ID 为 `827c01d6-0a9a-4e3e-bba8-db6a3aa3f5b5`，交付修订 2，960 条最终测量。三个背景条目是“超新星的历元测光、峰值与波段衰减”“颜色 消光与衰减的含义”“谱线通量与等值宽度”。最后一个条目出现在色余性质的输入背景中，其适用依据应在知识绑定检查中可见，不把条目标题本身当作匹配正确的证明。

这 86 次引用表示**程序选择并提供给生成模型的知识背景**，不是模型逐句声明使用的引用。当前生成协议只返回文本，不能把全部输入背景显示成“每句话均已引用”。

另一个区别：当前 insights GET 会在读取时补充通用理论背景。实际读取最新样例得到 2 个知识块、3 条一般理论关系；这些是读取时增强，不能视为该任务已生成并封存的性质级综合洞察。

## 二 知识在整个流程中的职责

| 流程位置 | 当前职责 | 本方案的安排 |
|---|---|---|
| 查询确认 | 固定规范版本、性质定义及知识发布版本组合 | 延续固定版本，再记录本次允许参与的用户知识快照 |
| 检索、提取、质检、规范化 | 使用性质定义、适用规则和执行能力；结果依据原始来源 | 保持此边界，解释性知识不取得科学执行权限 |
| 交付后资料阅读 | 用原件、表头、摘要与相关知识生成资料说明 | 保留，并显示原文依据与输入背景 |
| 交付后性质解释 | 旧策略有，新资料模式没有生成 | 恢复为互补的性质级综合洞察 |
| 科研追问 | 工具可检索用户/理论知识，也可读取已保存洞察；并非每次追问都必然调用 | 把任务固定的知识依据和两层报告统一提供给追问，额外现时检索单独标记 |

设置中的可编辑知识工作台、版本化的正式解释知识发布，以及规范化所用科学规范，不是同一层权限。用户优选只改变合格条目的排序，不能让不相容条目取得科学适用性或换算许可。

## 三 方案选择

方案 A 是只展示现有 `basis.knowledge` 和理论背景，改动较少，能立即解释“这段总结获得了什么知识输入”，但不会产生跨来源的性质级综合结论。

**推荐方案 B：保留资料级总结，补回性质级综合洞察，统一展示知识依据。** 它沿用新版按资料阅读的工作台，同时恢复旧六份样例有、最新样例没有的综合解释能力。不切换回旧前端，不另建知识系统，也不在数据提取前附加一轮自由推断。

这是本方案的工程推荐，尚不表示用户已批准具体协议、自动生成成本或历史样例补充运行。

## 四 后端衔接设计

### 在科学数据封存之后生成两层解释

采用新的固定执行策略，工程建议命名 `research-workbench/2`：

```text
查询确认并固定规范与知识版本
  → 检索 → 提取 → 质检 → 规范化 → 对照 → 科学数据封存并可阅读、导出
  → M11 父任务
       ├─ 资料总结：解释每份资料和每项性质
       └─ 性质洞察：综合同一性质的多份来源、测量与适用知识
  → 收集完成或明确失败状态 → 原子发布组合报告
```

两部分均从同一准确快照取数，互相不等待对方的模型输出。性质洞察不能把资料总结的模型文本当原始证据，输入仍为测量、误差、条件、原件证据和准确知识块。

沿用现有任务总预算、模型资格和能力校验，不自动追加额度。资料总结的 report-only 调用许可不能替代性质洞察所需的正常生成资格。预算或资格不足时，分别记录未生成原因，保留已经完成的报告与科学数据，不隐式换用另一模型或降低校验。

复用现有性质洞察的分批、综合、引用校验和检查点机制，保证全部目标记录进入覆盖清单；容量不足时继续分批或报告未完成部分，不静默只取前若干条。至少按已冻结的主体、波段、历元、单位、表示方式和方法条件区分可比较范围；未知条件明确限制比较。

### 两份子报告与一个组合报告

保留资料报告与性质报告各自的存储、生成状态、错误、输入哈希和模型回执。工程建议新增 `InsightBundle/1`，引用资料总结、性质洞察和知识上下文快照，并记录各部分的完成范围。

**不能直接在现有 InsightService 中连续调用两个会完成任务的生成器。** 当前 `finish_insights` 要求单一报告 schema，且资料生成过程中检查准确交付修订；若任一子任务提前提升交付修订，另一部分会收到 DELIVERY_CHANGED。

因此，新策略下子任务只保存自身结果和进度，不直接完成主任务或调用最终交付发布。M11 父任务在两部分均进入结束状态后，使用准确预期修订原子发布组合报告与新交付修订。生成期间仍可从已保存进度读取资料总结，科学数据维持原封存修订。重复调度采用快照、知识快照、协议和输入哈希去重；不能产生重复付费或互相覆盖。

原 `research-property/1` 和 `material-summary/1` 的读取、完成规则与历史报告不变。现有资料分页/详情保持兼容；组合模式通过 insights 的可选分区读取摘要、性质报告或知识依据，前端按当前分区加载。

### 统一准确知识上下文

在查询确认时固定正式知识发布，并为允许参与的理论库与用户覆盖层记录库版本、条目版本及内容哈希。生成前形成一次任务知识选择清单，两部分共享相同输入背景快照。

清单区分正式版本绑定、一般理论背景、用户自建/覆盖、可选候选及拒绝原因。匹配核对性质定义、输出配置、主体、类型、条件及兼容清单；显示色彩、优选排序不能放宽适用条件。自定义性质无精确绑定时保留来源事实，并明确“尚无匹配的知识解释”。

当前资料总结遇到知识发布不可读时会回退并继续；新版应保留“知识不可用”“无适用条目”“条件未确认”三种状态，不能都表现为无提示的空背景。

已保存背景按原文、来源、条件和版本读取。历史任务不在渲染时用用户当前编辑内容替换当时依据；现时知识检索以“当前补充背景”独立呈现，不能冒充归档结果。

### 科学结果与解释边界

洞察不覆盖原值、误差、单位、来源，也不自行取得规范化或科学审核权限。发现可能问题时生成待复核提示，引用具体记录和原件；需要改变采用状态或进行换算，走已有责任复核和版本发布流程，不能靠洞察正文静默改动导出内容。

理论关系只采用有出处的显式绑定、经确认的映射及其条件，标记为“一般理论背景”。性质同现或名称相似不构成本任务的实证相关性。

## 五 按新版工作台展示

不增加主导航，继续使用“数据结果 → 总结与洞察”。内部分为三个沿用现有胶囊样式的页签，默认保持资料阅读入口：

```text
总结与洞察
  [资料总结] [性质洞察] [知识依据]

资料总结：当前各性质完成情况 → 浏览对应资料
性质洞察：按性质展开综合卡片 → 定位测量与原件
知识依据：任务固定的背景条目 → 条件、来源、版本、对应位置
```

### 每份资料的详情

“提取总结”下增加轻量入口“原文依据”“输入知识背景”，展示已保存的 evidence 和 knowledge。直接复用现有覆盖式右抽屉和左侧模糊遮罩，中央布局不被挤压。

旧总结的知识标注为“提供给生成模型的背景”，不能包装为逐句引用。未来若需要逐句使用记录，应升级总结输出协议，返回允许列表内的实际知识/证据引用并校验；旧总结保持原貌，不补造引用。

抽屉展示知识标题、解释或公式、适用条件、来源、作者依据标签、用户修改状态、准确版本，以及“本资料作为方法事实”或“仅用于一般背景”的区别。任务当时版本与“打开当前知识库条目”分别提供入口。

### 性质级综合卡片

四类固定内容：本次取得的结果、不同来源的可比较差异、可解释的物理意义与理论背景、适用条件和限制。卡片必须显示数据覆盖范围、生成/部分完成/失败状态，以及可定位的测量和知识依据。

新 SN 2014J 可按其四项准确性质组织四张卡片，不把历元值、峰值、不同波段和不同时间定义混成同一批数值比较。没有足够依据时，保留事实阅读与缺口说明。

### 知识依据目录与图谱

展示本任务使用或提供的知识，不把整个知识库一次展开。目录按性质分组，区分正式解释依据、一般背景和用户知识。可选小型关系图表达“性质 → 知识 → 来源”，点击进入同一抽屉；关系须有类型、依据和适用范围。

统计分别显示去重知识条目数、输入背景出现次数、存在解释知识的性质数，以及实际生成完成率。不能把 86 次重复输入当成 86 条独立知识，不能把“有背景”当成“已完成性质洞察”。

普通组件与 Canvas 全部使用现有主题变量、系统五色和共享 Canvas 主题读取逻辑；不增加独立色板。保持学术样式、字体、图标、圆角、细边框及现有抽屉动效。

## 六 历史与演示样例

旧六份样例继续展示原 `InsightReport/4`，最新样例继续读取原 67 份总结。先把最新样例已有的背景和原文依据显示出来；性质洞察分区准确注明“此历史样例未生成性质级综合洞察”，不能显示成任务失败或凭空生成旧式卡片。

新组合策略只用于之后确认的新任务。已执行任务、运行中的固定版本任务、历史回放及已有导出均不自动升级。

如要让演示库展示完整新能力，应作为独立维护步骤，真实生成并验证一份采用组合策略的新演示交付，保留原样例包和原任务标识的历史读取。不会在打开样例、GET 请求或查看历史时自动调用模型补写。

## 七 实施次序与验收

1. 先展示已有依据：资料详情的原文与输入背景、知识覆盖状态、版本抽屉；旧样例正文不变。
2. 再接性质洞察：新固定策略、M11 父子报告、发布屏障、状态及版本校验；保留既有单模式路径。
3. 接入综合展示与追问：统一三分区、性质卡片、准确知识跳转和任务证据上下文，现时补充背景独立标记。
4. 用新组合策略真实生成演示交付，核对全量引用、完成范围、成本与历史兼容，再发布演示目录更新。

验收重点：

- 可从新版每份已生成总结查到其原文和当时输入背景；不存在的知识或逐句引用不补造。
- 新策略同时保留两份子报告，任一失败不会丢失另一部分或阻断已交付数据的阅读、导出。
- 两个子任务无论哪个先完成，均不会误触发交付修订冲突、提前完成主任务或重复付费。
- 大于模型容量的性质有完整分批覆盖记录；条件不相容的测量和知识不被混合使用。
- 更新、隐藏用户知识或切换知识发布后，既有任务仍显示原依据；新任务按新固定版本执行。
- 缺失知识、损坏引用、模型失败、预算耗尽、取消恢复、并发发布与回放时点均有明确状态。
- 前后端相关测试、构建与离线回归通过；旧六份与最新样例科学数据及原导出指纹不变。

本方案不引入新的科学算法、知识图数据库或 AI 自动建库，不把用户文本提升为已审核科学规则。

方案已完成一次独立可实施性核对，未发现必须由用户补充的重要信息；上述协议命名及父子发布屏障为工程推荐，实施前仍以用户对本方案的最终选择为准。
