# 加载速度与数据流转精简实施计划

> **实施状态：** 用户已于 2026-11-13 明确授权实施本方案。按测试先行、独立复核和最终回归推进；保留现有未提交改动与运行工作区。验证记录见 `docs/performance/2026-11-13-loading-speed-data-flow.md`。

**Goal:** 提升页面首次可用、筛选、切换和结果阅读速度，消除展示链路中无必要的传输、请求和计算。

**Architecture:** 使用轻量API投影、按页面依赖读取、精确版本请求合并、游标化展示投影和交付读索引。现有权威科学数据和命令处理继续负责正确性。

**Tech Stack:** 现有 React/Vite、FastAPI、SQLite、SSE及Worker；不引入独立缓存服务、消息中间件或图数据库。

**Spec:** docs/superpowers/specs/2026-11-13-loading-speed-data-flow-design.md

## Global Constraints

- 只优化本项目的加载与展示数据流；保留现有设计、系统配色和开发热更新。
- 保留此前按视图加载、分类搜索、取消旧请求、缓存复用和弹层关闭修复。
- 不改变科学执行资格、转换/质量算法、原始值及单位/误差/上限，不删除原始资料和历史交付，不修改已发布规范包。
- 不用延长刷新间隔掩盖状态更新，不跳过服务端版本、权限或科学校验。
- 所有写入与导出继续走现有成功确认、并发冲突及幂等契约；性能测试只使用只读真实数据或隔离测试目录。
- 当前工作区有大量用户认可但未提交的内容；保留这些改动，未经请求不提交、不切分支、不重置。

## Review Focus

- 列表变成真分页后，搜索、排序、重复/修改筛选和统计仍针对全部匹配记录。
- “全部匹配结果导出”不能退化为当前页导出，跨页选择和回放时点不能混淆。
- 对话组合读取不能丢失提问选项、审核证据、暂停/恢复能力或版本冲突检查。
- 取消一个共享请求的消费者不能取消其他消费者；过期响应不能写入缓存。
- 派生索引和缓存必须绑定精确版本/游标及协议，不将动态覆盖或最新结果套到历史记录。
- 索引缺失、损坏、构建中和跨版本迁移不能导致空白成功或永久等待。

## Task 1：基线与请求依赖清单

**Interfaces:** 为每个场景记录网络请求、未压缩JSON字节、服务端查询/解析/投影/序列化耗时、浏览器首次可用时间；诊断日志只记录端点/版本/计数，不记录密钥、研究正文或完整模型提示。

- [x] 记录首页、直接进入两个工作台、筛选、图谱/矩阵切换、新增编辑器、任务对话、结果首屏、单项详情、导出及回放的请求依赖表。
- [x] 固定当前样本与5000条隔离数据，准备可重复运行的浏览器和后端基准。每个关键场景至少30次，记录P50/P95及失败数。
- [x] 区分首次预检、首次读索引构建、冷前端缓存、暖读取；不将一次采样当作稳定性能结论。
- [x] 将“首屏必要/用户操作后需要/重复/导出专用”落实到每个读取调用，作为后续删改依据。

## Task 2：工作台摘要、目录、编辑数据分离

**Main surfaces:** 现有 registry/knowledge summary 服务与路由、工作台读取Hook及设置工作台；优先处理已实测最大的冗余负载。

**Public API additions:**
- `GET /api/registry-workbench/summary?projection=stats|directory|full`，缺省仍为`full`以兼容旧调用。
- `stats`保留现有统计、覆盖、活动组合、修订及草稿状态，省略`types/families/capabilities`。
- `directory`在统计上增加类型和分类目录，省略执行能力及转换策略；只按准确版本读取完整目录，不能被当前已选分类缩小。
- `full`保留原行为，仅在编辑器确实需要完整能力目录时读取一次。完整许可、来源与精确引用不裁剪。
- `GET /api/knowledge/summary`增加同名投影；`stats`省略性质选项目录，`directory/full`保留目录。缺省旧行为不变。
- 规范`workspaces/releases`列表增加可选`projection=directory`，仅返回选择/历史列表所需的ID、名称、状态、修订、时间和准确版本引用，不携带完整operations、validation或执行清单。缺省旧列表契约保留。

- [x] 写失败测试，验证投影白名单、默认兼容、完全相同的统计/覆盖、字段缺席以及版本/筛选一致性。
- [x] 新前端初次打开读取一次`directory`和当前图谱/列表；无筛选时直接复用目录响应的统计，不另请求`stats`。
- [x] 之后筛选只请求`stats`及当前视图。分类候选搜索继续本地执行，不发API请求。编辑器按需读取并复用`full`目录。
- [x] 版本列表/发布历史延迟到打开版本选择器或历史弹层时读取；保持加载/重试反馈和默认已发布选项可用。
- [x] 缓存按投影、版本/草稿修订、筛选与分页隔离；写入仍失效对应草稿全部受影响视图，不能错误复用旧数据。
- [x] 后端投影构造只访问所需字段；不能先深拷贝完整响应再删除大字段。复用已验证的不可变基础数据，拷贝范围限制在确实需修改的对象和返回边界。

**Targets:** 当前数据`stats ≤32 KiB`、不含能力的完整浏览目录`≤512 KiB`；普通打开和筛选请求中转换策略传输次数为0；只打开编辑器才传输完整能力。

## Task 3：合并公共读取与精确失效

**Interfaces:** 共用读取协调器以规范化请求、投影、准确版本、筛选、排序和分页作为key；仅GET可自动合并。共享网络请求由协调器持有AbortController，每个消费者有独立取消状态。

- [x] 写失败测试覆盖应用/设置同时读取配置、同页多组件读取同资源、StrictMode、消费者单独取消、全部取消、失败重试及旧响应。
- [x] 合并`App`和`SettingsDialog`的配置读取；共享服务器返回的可展示配置，用户输入的密钥草稿保持表单私有，不写共享缓存。
- [x] 根据当前入口延迟读取演示目录、未展开版本历史和未打开编辑器数据；已有任务的关键SSE状态/异常通知继续工作。
- [x] 只在最后一个消费者取消时中止共享请求；失败或取消不成为成功缓存。命令POST、幂等操作及保存失败草稿处理保持原样。
- [x] 为版本目录/不可变结果增加ETag条件读取；ETag必须包含准确版本、投影协议和筛选，动态覆盖另带库修订。服务器完成必要有效性检查后才可返回304。
- [x] 前端显式处理304：使用同key已验证缓存；本地副本缺失时只做一次无条件重试。“重新读取”仍向服务端确认有效版本。
- [x] 确认调用迁移完成后移除重复包装器、无调用的预取和整库刷新入口；保留外部API/CLI的默认兼容行为。

## Task 4：任务对话与预览刷新去重

**Public API additions:** `GET /api/tasks/{id}/state?view=chat`增加组合读取；旧`conversation/workspace`和`presentation`接口保留。组合响应包含现有对话所需任务/提问/审核数据与展示投影，共用同一`core_event_cursor`，消息和阶段内容只传一份。预览增加可选`preview_protocol=2`，缺省仍用旧协议；v2的`preview_revision/preview_id`为可见内容依赖的指纹，不能继续直接哈希task_revision/event_cursor。

- [x] 写失败测试：同游标新旧展示等价、未确认/等待审核/暂停/终态行为一致、事件乱序/间隙处理、修订冲突和历史回放不变。
- [x] 抽出接受现有只读事务和指定游标的任务/展示构造器，共享所需查询与解析结果；组合端点不得在内部机械调用两个完整HTTP服务。
- [x] 普通对话改为一次`view=chat`读取；结果/执行页继续使用已有轻量`workspace`读取。回放仍使用准确`at_seq`，不得改读最新状态。
- [x] 展示投影按源任务、游标、投影协议和展示参数缓存；事件读取限定在已处理游标之后，使用确定性累计状态及有界检查点。回放倒退可从不晚于目标的检查点恢复；缺失时重建。
- [x] 保留现有单飞和事件合并机制；事件只提示重新读取服务器权威状态，不能让前端据事件自行批准操作或越过审核。
- [x] 在同一只读快照中构造v2预览依赖指纹：确认查询/代次、测量版本、审核状态、采纳/排除处置、派生处理、证据视图及依据可用性等所有影响可见结果的变化均推进令牌；不相关日志、心跳或任务修订不推进。组合状态中的`preview_revision`和预览分页使用同一依赖规则。
- [x] 临时结果仅在v2内容令牌、分页或筛选变化时读取。请求携带协议及`expected_preview_id`，禁止混用新旧协议或拼接不同内容快照；旧调用者保留旧令牌校验。内容变化和代次切换立即失效旧读取，取消停止读取但不凭空改写保存内容。
- [x] 将当前任务控制/审核资格与可复用展示投影分开，命令入口仍读取权威状态并核对expected_revision。

**Targets:** 常规对话刷新由2个完整读取合并为1个；不变内容不重复投影；无关事件导致的预览请求为0。用完整事件回放逐字段对照原输出。

## Task 5：结果真分页与单项详情读取

**Public API additions:** 扩展现有records/sources的`view=list`，保留现有行结构、`items/total/offset/limit`及版本/快照字段，补充服务端搜索、排序和既有快捷筛选参数；materials/figures需要轻量行时采用同名`view=list`。现有显式`view=summary`及缺省消费者均保持原语义，不复用该名称定义新协议。来源、图像分别支持可选`source_id/figure_id`单项过滤，现有`record_id/material_id`复用。

**Data flow:** 复用`result_views.record_list/source_list`现有轻量基础，按需要增加小型来源标签/快捷筛选标记，避免再取整份报告。列表保留显示值、单位、误差/上限、状态和准确引用；完整定义、审核/处理轨迹、证据、正文、参数与图像内容进入单项详情。核心数值不因响应预算截断或重新计算。

**Export contract:** 现有`selection={mode:all|ids,measurement_ids:[...]}`不变。新增`selection={mode:"filtered",filter_version:1,filters:{...},excluded_measurement_ids:[...]}`，filters使用分页读取的同一规范化过滤器，不含offset/limit；排序不改变选中集合。服务端在既有导出事务内解析“全部匹配−取消勾选”，排除ID必须唯一且属于本次匹配集合，最终为空则报错。保留expected_delivery_revision、操作回放及序列化后修订复核；不开放历史修订生成新导出，历史原有下载行为保留。

- [x] 写失败测试：5000条结果首屏只取50条、服务端搜索/排序覆盖全体、跨页重复/修改筛选、单项详情和版本冲突。
- [x] 新建`readResourcePage`返回一页及总数；正常浏览迁出会`while(total)`下载全部页面的`resource()`/`getPreview()`。首屏50条，复用现有25/50/100分页样式，切换与返回保留条件、页码和阅读状态。
- [x] 把当前基于全量数组的搜索/排序和快捷筛选迁到服务端读模型。复用既有质量/重复组/修改结果，不能发明新的科学判定或只在当前页统计。
- [x] 记录页只读当前记录页及必要小摘要，不再为行上的状态标记下载整份quality、全部来源。打开一个记录/来源/图像时读取该项所需详情与引用，不ensure整类资源。
- [x] 预览采用同样真分页，分页请求带准确`preview_revision/preview_id`，变化时明确重新定位，不拼接不同临时快照。
- [x] 全局统计、分布图和覆盖图使用现有事实的服务端聚合，不在浏览器下载全部记录后重新统计。
- [x] 保留跨页选择；“当前页”使用既有ids模式，“全部匹配结果”固定使用新增filtered模式及排除集合。导出解析与分页共用过滤协议和准确交付修订，不能用当前页代替全部匹配，也不能绕过旧历史导出限制。
- [x] 旧历史适配器同样服务端分页；兼容原始报告与版本标识，不修改历史载荷。

**Targets:** 正常首屏请求不取第二页；当前数据及常规合成数据50条摘要`≤256 KiB`。图像/证据正文只有打开对应内容时读取。

## Task 6：后端只读索引与首屏代码拆分

**Storage:** 使用独立可重建缓存`runtime-data/cache/ui-read-models.sqlite3`，不迁移权威runtime.sqlite3中的历史载荷。读索引按源任务、交付ID、修订、原内容哈希、资源和投影协议绑定；同一精确引用的定义/来源只保存一份。

- [x] 对比“当前已有单快照缓存＋重复行投影”与新索引，先记录真实CPU/查询/解析成本；不得将现有快照缓存遗漏后声称消除了不存在的重复解码。
- [x] 新交付与历史交付均在首次读取时构建摘要行、筛选索引、总数及现有质量标记（实施取舍：避免把 UI 缓存构建失败加入科研发布事务）。每个key单飞构建，事务提交完成前不可见，禁止半成品索引被当作成功结果。
- [x] 页面请求先过滤、排序、分页，再序列化本页；单项详情读取对应原始对象。索引命中不重新遍历完整交付。
- [x] 索引缺失/损坏时保留原来的正确读取路径并重建；源哈希/协议不符直接失效。重建不改变任务事件、交付引用、科学许可或已封存文本。
- [x] 工作台/结果中尚未打开的编辑器、导出、重图表和历史弹层使用现有React.lazy机制按操作加载；首屏保留必要目录、搜索和视图。现有主题变量/动画/焦点规则复用。
- [x] 保持原科学预检与模型执行启动条件。若加载瓶颈仍来自科学包初始化，将其耗时单独报告；本轮不通过跳过校验或重写302MiB科学输入格式取得加载成绩。

## 执行顺序和默认取舍

按Task1→2→3→4→5→6→7推进；Task5的分页契约在Task6索引上线前先走现有正确读取路径，因此可以分别验证，禁止一次性替换整条科研链。

先完成接口瘦身、请求合并和数据依赖清理，再做展示投影/结果读索引。保留合理热点缓存，不把内存降低作为本轮主验收。首次进入详情允许额外的小请求，以换取首屏不搬运无用正文；数据完整性和版本准确性优先于请求数量绝对最少。
