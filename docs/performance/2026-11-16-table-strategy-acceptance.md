# 大表、普通表与恢复策略复核

本轮沿用既有提取、统一质检、清洗和对照管线，前端接口及历史结果不变。

## 修正

- 同表历元分离只证明表内记录不同。小规模跨源记录仍合看原件；大规模记录先做表内索引，再查看包含所有记录的性质索引，选择需要合看原件的跨源组。全局索引超限或跨源原件核验失败，结果保持 partial，不能宣称全量完成。
- 已有真实列定义或 ReadMe 的重复质量码、限制标记，可以逐行抄录为待独立质检候选。标记、对象和非共享条件保持分组边界。独立质检必须为每个固定标记返回实际 E 证据、原文引句、原始标记及适用限制；程序核对逐行原值、单位、误差、条件和行列位置。缺定义、复合值、未知标记、不能共享的语义继续走原有原件解释与定向重提。
- 列计划分别保存付费解释的 interpreted_plan、过滤后的 plan、排除依据和模型曲线排除记录。恢复后重用同一原件和性质哈希，不因空计划丢失排除理由。
- 共享质检版本改为 shared_semantics/3-source-flag-rules；新证据或新版本不会复用旧范围判断。已完成的历史判断不重写。

## 验收边界

- 同条件数据仍逐行读取、计算和核对；优化的对象是重复科学语义的模型调用。没有抽样替代全量原件核验。
- 10,001 行合成数据用于路由、分组调用量和逐行原件覆盖测试，不作为科研效果证据。
- 保存的 2,391 行真实附表用于整列不适用判断复核；它不是 2,391 条已接受的科学测量。
- 保存的 12 条真实测量及独立模型响应用于批量路径与普通路径的原报字段对照，没有追加付费调用。
- 恢复测试覆盖付费响应已保存、共享判断已保存但行级决策只写入部分、列计划写入后进程中断，以及例外批次额度用尽。只处理尚未完成的行，局部问题不静默当作通过。
- 执行冻结记录、测试统计、原件重放结果和实际查询结果保存在本次交付目录。演示历史加载中此前已复现的旧测试故障独立记录，不计为本次策略通过项。
