## 已实施

1. 解压采用有界预读，与 SQLite 写入重叠执行。两个队列槽各最多 1 MiB，生产者最多额外持有一个块；不预解析并积累大对象。标准 BufferedReader 继续处理长行、UTF-8 和换行，JSON 与科学内容保持原字节及顺序。
2. 完整导入事务仍等待 FULL WAL 持久提交成功，再对外显示任务。提交后的 checkpoint 页整理使用单个后台维护线程，能与后续读取重叠；准备失败、维护槽忙或引擎不满足条件时，走原有同步路径。关闭应用时等待维护退出。
3. 不放宽外键、事务、压缩包哈希、快照身份、表结构或所属任务检查；不修改样例包格式、科研规则、历史任务、导出与前端样式。

大缓冲、32 MiB SQLite 缓存的两轮对照没有稳定收益，未采用。保留预读的依据是另两轮隔离对照：仅后台页整理导入 8.458／8.423 秒，组合方案 7.881／7.869 秒。

- 本机 SQLite 为 3.53.2。后台 checkpoint 只在具有 WAL-reset 修复的引擎启用：3.51.3 及以后，或官方回移修复 3.50.7／3.44.6 分支及以后；其余版本保留原路径。

SQLite 的 FULL WAL 提交与后台 checkpoint 是两个不同阶段；后者的调整没有替代前者的持久化保证。依据为 [SQLite WAL 说明](https://www.sqlite.org/wal.html) 和 [synchronous 说明](https://www.sqlite.org/pragma.html#pragma_synchronous)。上述版本守卫依据 [官方 WAL-reset 修复说明](https://www.sqlite.org/wal.html#the_wal_reset_bug)。
