# 新样例与科学库加载优化验证报告

2026 年 11 月 13 日。本轮保留现有科学库、样例包、权威任务数据库和前端设计，优化进程内重复计算与资料读取。完整科学校验通过后才允许执行新科研任务；历史阅读不等待当前默认科学库预检。科学校验与重复打开速度达到目标，最大样例首次导入及建索引仍未达到 8 秒目标。

## 已交付的变化

- 科学编译按准确版本与输入建立一次引用、定义、输出配置、规则、决策节点和转换策略索引；418 个上下文继续各自校验。投影复用以实际依赖和协议为键，返回副本；沿用应用持有的规范服务与现有加载锁，不添加跨进程成功标记。
- 样例按 ID 合并并发导入，采用有界批量写入；SQLite 写阶段在事务外排队，保持完整事务、外键、包哈希、身份检查及用户同 ID 任务优先。
- 在可重建 UI 缓存增加准确交付版本的头、资料和逐项详情索引，原子发布完成标记。大交付并发构建只解码一次；命中索引后不再整包解码。损坏、磁盘写入失败和旧式局部快照保持原有正确读取路径。
- 资料分页缓存最多 32 项、8 MiB；250ms 搜索防抖、取消旧请求、写入失效和多消费者隔离。静态资料不重复保留在底层 ETag 缓存中；动态总结采用轻量投影，隐藏页面停止请求。
- 清理初次读取已完成历史任务时误触发的完成通知，消除额外的查询列表刷新。真实运行任务的完成通知保留。

导出、执行资格和科研执行仍读取权威数据。未修改科学规则、发布包、历史交付、导出范围或颜色样式文件。

## 性能测量

科学冷初始化使用 5 个独立 Python 进程。样例接口在隔离临时数据库分别运行原代码与最终代码，固定哈希种子以隔离原有集合遍历顺序差异；各版本暖接口采样 30 次。浏览器使用完整生产 App、真实资料卡片和两次动画帧确认，第一次单列，随后 30 次暖打开。

| 项目 | 优化前 | 优化后 | 结论 |
|---|---:|---:|---|
| 完整科学初始化 P50 | 14.452 秒 | 7.395 秒 | 保留全部校验 |
| 完整科学初始化 P95 | 14.751 秒 | 7.628 秒 | 降低 48.3%，达到目标 |
| 大样例交付头 P95 | 2325ms | 115ms | 响应仍为 477 字节 |
| 大样例资料分页 P95 | 2403ms | 278ms | 响应仍为 14128 字节 |
| 30 次交付头整包解码 | 30 次 | 0 次 | 索引命中 |
| 30 次资料页整包解码 | 30 次 | 0 次 | 索引命中 |
| 浏览器暖打开 P50／P95 | — | 345／372ms | 30 次，真实资料首屏 |

浏览器第一次打开已有持久读索引为 473ms；另一次后端重启后的已有索引打开为 614ms。这两次单次测量不是“30 次独立重启 P95”，也不包含首次导入或首次建索引。

最终主服务再次重启后，工作区、交付头和资料首页顺序读取分别为 108ms、143ms、834ms，合计 1.086 秒；随后各 30 次主服务 API 读取，交付头 P95 为 208ms、资料页 P95 为 331ms。该结果验证持久索引跨进程复用，不代表首次导入达到目标。
