# 附表与星表：按来源解释语义，逐行核对原件

本轮保留查询范围、模型分工、独立质检、单位转换约束、人工判断和原件溯源机制。优化重复工作，不以抽样替代逐行核验，也不把同单位当作同一物理量。此前的单次查询缓存优化继续保留。

## 实际瓶颈

真实 CDS 附表 `J/A+A/585/A19/table2` 有 2,391 行。其原始字段说明是 `SN-S1 magnitude difference`；冻结查询请求的是峰后 15 天衰减量 Δm15。原表头计划已指出两者不同，却留下 `quantity_match=unresolved`，因而不断进入每组最多四条结果的行级模型提取。瓶颈发生在提取阶段，并非单纯因为多源对照要比较 2,391 个数值。

本次在原任务上复用已付费的表头结果，只追加一次剩余的共享表头复核。模型明确认定该列是不同物理量；现有排除规则记录原始列定义和原因，不将差分星等充当 Δm15，也不计算替代值。原始 194,319 字节 VOTable 完整保留，SHA-256 为 `d3c2b4e3387dfcbe524e79fd29a4f0761db8b8ba4532bc6b9c30f79541ab6178`。

新增调用实测：输入 3,035 token、输出 228 token，从派发到结算约 3.6 秒，账面估算 0.003044 元。任务中的该附表作业已成功结束。原有错误路径若从头按四条一组处理，至少需 598 组；这个数字是批次数估算，不是已实测的整次查询节省调用数。此前已经发生的费用照常保留，未删除或冲销。

## 各环节的修改

| 环节 | 减少的重复工作 | 保留的判断与回退 |
|---|---|---|
| 表头/列定义 | 将未确定的物理量关系纳入同一个、最多两次调用的表头预算，先在列级澄清 | 无法确定、依赖行内容、缺少字段依据时，继续原有行级解释；格式修复、元数据补全和语义复核共用两次上限 |
| 断点续跑 | 同一不可变来源、定义和表结构的已付费表头不重跑 | 只有尚未用掉共享复核次数的旧计划可再用一次；不跨来源复用，也不获得第三次调用 |
| 数值提取 | 对已有对象行凭据、物理量明确、普通有限数值的单元格，由程序原样收集 | 只形成待质检候选，主体和结果角色保持未确定；不能据此直接准入。质量码、限制值、复合单元格和不明单位保留原提取路径 |
| 独立质检 | 同一原件、目标、性质和条件组共享独立的语义判定；光度测量字段可作为数值变化项 | 每行重新打开原件，核对对象凭据、行列、原值、单位、误差与条件；方法、标记、标识和非数值编码仍分组；模型必须明确声明语义可复用并引用真实证据编号 |
| 误差解释 | 质检可为同组的普通标量误差建立一次列级模板，逐行绑定各自原报数值 | 角色、置信水平和统计含义仍需原文引文。非对称、相对、矩阵、负数/哨兵和复合误差不套用该模板；未获可用模板时定向重提，不能悄悄丢失误差含义 |
| 单位清洗 | 每条测量只加载其实际引用的单位与误差基准，按引用版本取值，免去反复扫描整批单位记录 | 仍使用原有科学许可、Astropy/Decimal 数值计算和独立校验；不猜单位、星等零点或对数参考值；不合并误差分量 |
| 对照 | 对现有历元分组内的波段计数改为线性计数，避免大重复组内反复计数 | 原有科学对照机制保留。不同有效历元、波段、条件不因数值接近而删除；同源重复保留出处；需模型/人工判断的情况仍走原路径 |

共享语义的缓存键绑定原件哈希、表结构/说明、目标、冻结性质和模型；误差模板使用新的内部作用域版本，不能套用旧的无模板判断。共享提取仅在现有 `shared_semantics/1` 质检策略启用时使用；旧的独立处理策略仍沿用原提取机制。

## 验证范围和限制

- 合成回归覆盖 2,391 行完整收集和 10,001 行逐行原件核验，检查零值、负主值、原报精度、误差、条件、错行、缺失、质量标记和独立回退。
- 真实正常测量验证使用现有 SN 2014J 官方附表中的一个 12 行同条件组。正式非思考配置下的独立质检生成共享判定和误差模板，全部 12 行逐条机械核对通过。该组最终用了两次调用（含一次协议修复）；不把它说成一次调用，也不把该组结果推广到整张 162 行表。
- 首轮两次质检校准误用了测试配置默认的思考模式。它们未进入生产结果，费用保留在验证账本；之后使用与生产相同的非思考配置另行复验。
- 真实验证均使用原材料；未重跑旧基线，未生成假数据，未将校准回答写入正常查询的科学结果。完整查询保持暂停，没有后台付费验证继续运行。
- 此轮不能给出整次查询的固定节省比例。表定义明确且重复记录多时收益大；条件/标记变化多、误差形态复杂的来源仍需更多逐条判读。保留这些回退是科学约束的一部分。
- 回归数量、实际校准费用、Windows 原生启动自检和交付文件哈希见同包验收记录。完整回归排除已有且在未改动版本也失败的演示加载时延测试；相关模块另行执行最终针对性回归。

Windows 包从白名单源文件的不可变快照构建；不打包用户数据库、API 密钥或验证运行目录，不覆盖已有安装和原始任务。
