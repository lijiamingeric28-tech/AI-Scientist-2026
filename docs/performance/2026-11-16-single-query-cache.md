# 单次查询内的模型费用优化

本次保留现有模型、思考模式、页图分辨率、检索范围、阅读批次、独立原件核验、人工判断、修复次数和交付协议。没有引入跨会话科研答案缓存，也没有通过放宽 JSON 或科学校验减少重试。

## 实现

- 统一网关对论文提取、原件核验、结果对照的输入 JSON 仅重排顶层字段：固定 schema/规则在前，查询口径随后，动态候选、原文和修复信息在后。嵌套值、数组次序、页图与原始证据均保留；全局 `canonical()` 不变，科学对象的身份与哈希规则不变。
- 先使用平台自动隐式缓存。同一任务、模型、规则版本、连接和固定前缀已有至少两次用量完整的成功调用，观测命中不足 50%，且至少还有两项同类作业时，才尝试显式缓存。取得真实前缀 token 数后，按当前模型的实际两种读取价格比较收益；隐式方式能命中更长内容且更便宜时，保留隐式方式。过期重建的溢价仅按已排队工作摊销。没有额外预热请求，也不等待缓存而暂停正常工作。
- 显式缓存使用独立的同角色消息容纳固定 JSON 字段，其余字段及原图留在后一条消息。两个 JSON 对象的字段不重叠，合并后等于原输入。原件核验还缓存本次查询不变的完整身份与性质定义。真实多模态测试表明，同一消息内仅拆 text 块会把整条消息计为缓存写入，故未采用该方案。
- 固定前缀不足 8 KiB、非已识别的百炼北京端点、未支持的模型、输入没有额外 65 token 安全余量时，保留隐式方式。显式创建期间的并行调用继续走隐式方式，不排队预热。服务拒绝缓存标记或接受后未生成缓存时，该前缀回退。
- 成功的同作业、同完整输入、同配置调用使用 singleflight；不同作业的独立核验和修改后的反馈分别执行。网关在同一个账本事务中保存已完成响应，防止在费用结算后、普通步骤保存前崩溃造成重复收费。未知是否发送或未完整返回的响应不当作已完成结果复用。
- 每次调用，包括失败调用，保存原始 `usage`、逻辑输入哈希、实际发送哈希、缓存方式和价格版本。费用拆分普通输入、缓存读取、缓存创建和输出；思考 token 仅作为输出子项记录，不重复加价。创建溢价纳入预占费用，缺少缓存明细时保守计费。
- 旧账不重写。缓存折扣估算与标准价估算同时留存；二者都不冒充账户实际账单。校正旧版显示口径不计为新增优化收益。

## 配置与回退

环境变量 `ASTROQUERY_PROMPT_CACHE_MODE`：

| 值 | 行为 |
| --- | --- |
| `auto`（默认） | 重排前缀；满足上述条件时尝试显式缓存 |
| `implicit` | 仅重排前缀，不发送显式标记 |
| `off` | 保留原输入组织，不发送显式标记 |
| `explicit` | 已识别端点和足够长前缀上直接测试显式方式；用于隔离协议验证 |

平台的自动隐式缓存无法通过此本地开关关闭。费用记录和同作业完成响应恢复不依赖此开关。策略记录只在任务内统计，最多保留 256 个前缀，五分钟过期；凭据仅参与内存中的身份哈希，不写入回执。

## 验证与边界

隔离验证目录：`D:/Astroquery/deliveries/single-query-cost-20261116/`。验证库复制原库账本并保留原科研材料，原始库未被修改。完整查询通过常规创建、口径确认和执行器运行，不注入检索资料或历史模型输出；新增人工判断问题保留正常处理。

- 后端回归合计 1,527 项通过（含当时已加入的缓存测试；排除已确认在未修改 HEAD 上同样失败的旧演示导入测试文件）。该文件中 5 项检查点维护测试在两版均失败，不属于本次费用改动。以下定向组合与该总数有重叠，不累计相加。
- 最终缓存、网关、预算、限流、输入容量与失败派发组合：84 项通过。新增测试覆盖输入语义及原图保留、独立判断隔离、并发合并、崩溃恢复、创建溢价、未知用量、严格 JSON 拒绝与回退，以及隐式命中更长时避免错误切换。
- 新边界的六组真实材料调用均通过现有解析/科学证据校验：两组原件核验、两组论文提取、两组原件对照。后续调用分别命中 6,134 和 7,048 个固定前缀 token，计入首次创建费用后净节省为正。具体逐次用量和科学证据见隔离目录回执。
- 扩展原件核验的查询口径前缀后，两组共 12 条真实数值的原件核验通过，后续读取命中 7,600 token。向论文提取扩展同样边界的试验出现必填字段缺失，未纳入最终提取策略。最终核验消息与已通过的扩展核验测试、最终提取消息与此前通过的提取测试分别进行发送哈希比对，均逐字节一致；没有放宽校验来接受试验失败的条目。
- 本次只启动一条优化版完整 SN 2014J 查询；不重跑旧基线。执行过程和最终汇总在隔离目录保存。完整查询结果尚需以其最终交付及人工处理状态为准，不能用局部通过宣称整体效果完全相同。

输出 token 和首次出现的动态原件仍正常计费；缓存折扣不等于整单折扣。跨日期完整查询还受外部资料服务和模型采样影响，调用数量差异不直接归因于缓存。实际节省应优先由同一批调用的缓存用量及创建费计算，并与已存档的旧运行分开解释。
