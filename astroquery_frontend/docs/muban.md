## P2｜作品核心主张与实际完成内容

### 1. 本作品核心主张

- **本作品服务的具体科研数据需求：** 为天文学研究提供目标天体（恒星、星团、星系等）关键物理参数（金属丰度、质量、距离、年龄等）的多源统一结构化数据：研究者以自然语言提问，系统自动完成来源查找、数值提取、字段对齐与来源标注，输出可直接用于论文汇总、参数对比与后续分析的 JSON/CSV 数据。
- **本作品实际完成的核心方法：** 自然语言意图澄清 → 性质标准化（SIMBAD 天体解析 + RAG 性质库 + Qwen 选性质，生成全系统字段白名单 PropertySpec）→ 并行多源检索（25 个 VizieR 星表 + ADS 论文 + 开放获取 PDF + CDS 补充表）→ 多模态提取（Qwen-VLM 提取正文/表格/图表数值 + bbox 定位）→ 五阶段质量管线（评估/规范化/冲突/导出/洞察，含 Normalization↔Conflict 闭环）→ 带来源追溯的结构化输出。
- **最有代表性的结果 1（数据或任务范围、采用的方法、实际结果）：** Pollux（北河三，K0III 巨星）多性质多源协调：真实查询"Pollux 的质量、半径、视星等、光谱型和表面温度"，系统自动整合 13 个来源（4 星表 + 9 论文）、21 条记录，5 个性质数值与文献偏差 <2%——质量 1.7~2.31 Msun（文献 1.91，四种独立方法交叉）、半径 8.8~9.3 Rsun（文献 8.8）、温度 4893~5000 K（文献 4860）、光谱型 K0III 一致。
- **最有代表性的结果 2（数据或任务范围、采用的方法、实际结果）：** 质量管线完成 V1→V2 两轮闭环：评估发现 20 项问题 → 规范化修改 6 处（单位符号 M_sun→Msun 统一、字符串数值化、精度规整，全部记录 data_trace）→ 冲突解决 1 处 → **剩余问题 0**；综合评分 **0.9277（excellent，目前最高）**，处理统计 17 次 LLM 调用 / 89 次工具调用 / 160 秒 / B⇄C 循环 2 轮。
- **目前仍存在的主要局限：** ① 双星/多星系统实体消歧未解决（天狼星 A/B 参数混淆）；② 多波段星等的波段级拆分未实现（3C 273 BLL 各波段星等混存）；③ 单位归一未全覆盖（自行 mas/yr 与 arcsec/yr 并存，差 1000 倍）；④ VCR 回放模式存在数据错位风险，数据正确性验证需用真实模式。

### 2. 团队实际解决的问题

> *说明要求：用一段话说明在真实科研过程中，现有数据查找、整理或整合方式存在哪些具体不足，本作品希望解决其中哪一项或哪几项。不要重复赛事背景。*

在天文学日常研究中，研究者获取目标天体参数通常依赖人工：先在 SIMBAD 确认天体标识与坐标，再逐个查询 VizieR 各目录，下载相关论文后逐页阅读，手工摘录金属丰度、质量、距离等数值并记录出处。这一过程存在明显不足：① 来源分散（25 个星表口径不一 + 数十篇论文），人工比对费时；② 数值单位与量表不统一（如金属丰度有 dex 与 log(Sun) 两种写法），换算易错；③ 来源与证据无法追溯，复现困难；④ 多源数值冲突时缺乏系统化判断与标注。本作品希望解决其中的核心痛点：把"自然语言提问 → 多源自动查找 → 数值提取 → 字段/单位对齐 → 来源标注 → 质量检查"整条链路自动化，输出可直接复用、可溯源的结构化数据。

### 3. 本作品实际完成的工作

> *说明要求：用一段话概括已经实现的功能（如科研数据需求理解、数据源发现与筛选、正文/表格/附件/图表解析、字段和单位对齐、多源整合、来源保留、质量检查和反馈修正等；没有实现的内容不必写）。*

本作品已实现：① 科研数据需求理解——意图澄清（HITL，5 个澄清点）与性质标准化（SIMBAD 天体解析 + 100 文件 RAG 性质库 + Qwen 从库中筛选目标性质，生成全系统字段名白名单与标准单位表 PropertySpec）；② 数据源发现与筛选——25 个 VizieR 星表按 SIMBAD 别名匹配、ADS 论文检索（检索式由 Qwen 按性质分组生成）、Unpaywall/arXiv 开放获取 PDF 下载、CDS 补充表识别；③ 多类型内容解析——PDF 正文/复杂表格/科研图表经 Qwen-VLM 多模态提取，配合 bbox 定位与图证裁剪；④ 字段与单位对齐——列名到标准字段映射、单位换算（34 组/257 条规则）；⑤ 多源整合与来源保留——EAV 结构 + provenance 溯源元数据，冲突保留并分类标注；⑥ 质量检查与反馈修正——评估/规范化/冲突/导出/洞察五阶段，Normalization↔Conflict 闭环（最多 3 轮）+ HumanReview 人工兜底。

### 4. 本作品形成的完整闭环

> *结构建议：科研数据需求 → 来源查找与筛选 → 内容解析 → 字段与单位对齐 → 多源整合 → 质量检查 → 问题修正 → 结构化数据输出。*

- **本作品最终形成的主要数据成果：** 对每一次查询产出带来源追溯的结构化数据包：grounded_data JSON（schema 2.0.0）+ 长表/宽表 CSV + 质量评分、元数据、溯源、洞察、清单共 8 个导出文件，以及图证 PNG（Pollux 案例 10 张）。
- **本作品已经实际处理的数据来源和任务范围：** 已实际处理 25 个 VizieR 星表（Gaia/2MASS/WISE/SDSS/MWSC 等）、ADS 论文检索、Unpaywall/arXiv PDF、CDS 补充表、SIMBAD 天体解析；代表案例为恒星（Pollux），另已实际处理球状星团（M13）、疏散星团（昴星团）、变星（造父一）等天体类型，性质涵盖质量、半径、金属丰度、距离、年龄、温度等。
- **相较通用检索或人工复制整理，本作品最主要的不同：** 相较通用检索（只返回文档列表）或人工复制整理（费时且难追溯），本作品打通"需求理解→查找→解析→对齐→整合→质检→输出"完整闭环：以统一字段白名单 PropertySpec 约束所有提取路径，以 provenance 保留每条记录的精确出处（论文页码+bbox / 星表行列），以质量管线对多源冲突做系统化判断与标注而非简单合并，最终输出可复现、可追溯、可下载的结构化数据。

| 实际采用的评价内容    | 具体评价方法 | 评价对象与样本 | 结果如何影响后续处理 |
|:------------ |:------ |:------- |:---------- |
| 字段正确性  | outlier 检测 + 物理可行性范围检查 + 可选 LLM 完整性检查（缺失预期字段）+ extraction_quality 维度 | 每个来源的记录字段；本次 Pollux 案例 13 来源 / 21 条记录，per-source 并行 8 worker | 低质量字段路由到规范化修复或 HumanReview |
| 来源可回溯性 | trace_id + provenance 元数据完整性检查（论文 page/bbox、星表 db_table/key_column、补充表 cds_table_id/row_index） | 每条记录的溯源元数据 | 溯源缺失的记录标记，无法回溯的不纳入最终导出 |
| 冲突处理质量 | 多源方差分析（Cohen's d 统计冲突）+ 差异分类（方法/条件/时间/测量不确定度/重复/未知）+ 置信度标注 | 同一 entity+field 的多源值（如 13 条金属丰度） | 冲突保留全部并标注（preserve_all），单位错误生成可执行修正动作 |

### 2. 评价口径说明

- **团队重点评价哪些方面，为什么：** 字段正确性（数值合理性）、来源可回溯性（能否追到出处）、冲突处理质量（多源不一致能否被识别并标注）——三者分别对应"数据能不能用、能不能信、能不能查"。
- **抽样数量、抽样方式和评价主体：** 评价主体是确定性剖析器（0 LLM）+ LLM 辅助完整性检查；per-source 并行（8 worker）；本次 Pollux 覆盖 13 来源全部记录（全量非抽样）；质量评分带 Bootstrap 95% 置信区间（B=1000，固定种子 42）。
- **正确、错误、缺失、冲突和无法判断分别如何定义：** 正确＝字段值非空、符合目标 schema 单位、在物理可行性范围内、溯源完整；错误＝格式非法、单位不一致、数值超出物理范围、bbox 非法；缺失＝预期字段无值（completeness 维度）；冲突＝同一 entity+field 多源值差异超阈值（Cohen's d）；无法判断＝来源信息不足无法分类，标记 undetermined。
- **修正前后是否采用同一评价口径；如有变化，原因是什么：** 是——评分口径（维度权重/物理范围/冲突阈值）在规范化前后保持一致；变化仅在修正轮次（规范化修改后按同一口径重新评估，保证 V1/V2 可比）。

### 2. 数据闭环的关键设计

> *说明要求：请说明本作品为什么不是一次性检索或内容摘要，以及质量问题如何返回查找、解析、对齐或整合环节形成修正。*

本作品不是一次性检索或内容摘要：检索出的多源记录会进入五阶段质量管线，质量检查发现的缺陷会回流到对应环节修正——评估阶段对每个来源打分并做决策路由（质量等级 × 修复成本矩阵），格式/单位/缺失问题路由到规范化（单位换算、字段标准化、缺失处理、去重，修改记录到 data_trace）；多源数值冲突路由到冲突子图（方差聚合 + 差异分类，保留全部测量值并标注）；规范化与冲突之间通过 loop_controller 形成闭环（最多 3 轮，本次案例实际 2 轮）；无法自动修复的问题路由到 HumanReview 人工裁决。修正后数据重新评估，直至剩余问题归零或达到迭代上限，最后导出并生成洞察。这样质量问题不是"检查后丢弃"，而是"发现→回流→修正→再评估"的闭环。

### 2. 上下文组织与约束控制

- **团队为减少无来源生成（幻觉）、字段错配或错误合并实际采取的措施：** ① 性质白名单 PropertySpec 约束所有提取路径，模型只能从库中选择，臆造 property_id 被过滤；② VLM 提示要求显式页码映射，杜绝页码幻觉；③ 提取记录置信度低于 0.7 丢弃，bbox 非 4 元素/越界丢弃（不伪造坐标）；④ 卡7 总结 _is_usable_summary 校验，拒绝检索 JSON/工具代码等错位响应透传；⑤ LLM 生成代码沙箱执行（AST 白名单 + 空 __builtins__ + 线程超时），低置信度代码不执行；⑥ ADS 检索式被拒时把错误回喂模型重建。
- **上下文在数据查找、解析和修正前后如何更新：** 查找前：性质选择把用户需求 + SIMBAD 类型 + 候选库一次性注入；解析中：每个来源的检索结果（星表记录/论文下载路径）回填到下一环节上下文；修正前：评估阶段生成的 profile（字段统计/异常/缺失）注入规范化与冲突 agent；修正后：data_trace（before/after/tool/reason）累积，冲突循环每轮把上一轮标注结果回喂；ADS 检索式构建失败时把 ADS 拒绝原因回喂模型重建。
- **该设计对数据结果带来的实际变化：** 代表案例（Pollux）质量分 **0.9277/excellent**（当前最佳），评估发现 20 项 → 规范化修改 6（M_sun→Msun 等）→ 冲突解决 1 → 剩余 0；17 次 LLM 调用 / 89 次工具调用 / B⇄C 循环 2 轮；5 个性质数值与文献偏差 <2%。其他真实运行：昴星团 0.9015/excellent（距离 116~137 pc 与文献一致）；M13 0.8832/good（金属丰度 13 条跨源一致）；大角星 0.8954/fair（评估 54 → 修改 20 → 冲突 4 → 剩余 0）。

> *选择两个实际来源中表示同一内容的字段或记录，展示原始写法、团队采用的统一规则和最终结果；如不能可靠统一，说明如何保留原始内容。*

同一物理量恒星质量在两个来源写法不同：2009ApJ...702..672C 给出 "1.7 ± 0.4" 且单位为 **M_sun**（不确定度混在值里、单位符号不规范）；2009A&A...504..231A 给出 "2.31" Msun（标准写法）。统一规则：规范化阶段识别 M_sun 与 Msun 为同一单位的不同符号，统一到标准单位 Msun；数值中的不确定度剥离为纯数值（原写法保留在 raw_field/context），每步修改记录到 data_trace（before/after/tool/reason）。统一结果：质量记录全部归一到 mass（Msun），数值可直接计算比较（1.7~2.31 Msun，四种独立方法）。仍无法确认：v_mag 0.91（合成测光）与实测 1.14~1.16 差异超过方法误差范围，保留原文并标注"待核对"，不强合并。

### 2. 真实失败与边界

| 典型失败或边界问题  | 实际表现 | 原因分析 | 当前处理方式或支持程度 |
|:---------- |:---- |:---- |:----------- |
| 双星/多星实体混淆（天狼星 A/B） | 天狼星查询中 A 星（2.06 Msun）与 B 白矮星（1.0 Msun、0.008 Rsun）参数混在同一实体 | VLM 提取无"子实体"意识；SIMBAD 主标识指向系统整体 | 尚未解决；改用单星目标回避（Pollux 案例） |

### 3. 应用与成本综合说明

- **结构化数据已经如何被下载、分析程序或后续科研流程使用：** 导出 grounded_data JSON（schema 2.0.0）+ 长表/宽表 CSV + 溯源/洞察文件，可经浏览器直接下载或 open-file 本地打开；已实际用于参数汇总核对与多方法测定交叉验证（如 Pollux 四种质量测定方法对比）。
- **相比现有方式节省或增加了哪些成本：** 单次查询约 15-25 次 LLM 调用 / 90-140 次工具调用 / 100-160 秒（Pollux 实际 17/89/160s），相比人工查星表+下载论文+逐页阅读（数小时/天体）显著节省时间；新增成本为 LLM API 调用费（百炼按量计费）。
- **必须由研究者判断或人工审核的内容：** 跨源冲突的最终取舍（系统保留全部并标注，采纳由研究者定）；HumanReview 环节（跨标识错误、关键缺失）裁决；异常值（如合成测光 0.91）是否排除由研究者判断。
- **尚不能支持的数据来源、学科范围或复杂情况：** 双星/多星系统的子实体分离；多波段星等的波段级拆分；光谱原始数据；需付费/受限访问来源；非天文领域数据；B1950 历元坐标自动转换（仅格式归一化，历元未统一）。
