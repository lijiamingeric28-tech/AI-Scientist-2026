PROBLEM & VISION // 愿景

把数周的文献苦力，交给一条智能体流水线。

科研数据散落在星表、论文与补充材料之间：字段命名不一、单位各异、可信度未知。 传统流程要靠研究者人工检索、阅读、誊抄、核对数百篇文献。 AstroQuery AI 把这一切交给智能体，只留下一个最关键的问题 —— 提取到的每一行数据，质量是否可信？清洗依据是什么？

SYS-01 // FRAGMENTED

异构多源割裂

VizieR 星表、ADS 论文、CDS 补充材料，每个来源的字段、单位、精度都不相同，人工对齐试错成本极高。

SYS-02 // MANUAL READING

人工阅读誊抄

关键数值埋在 PDF 的表格与图谱深处，逐篇阅读、誊抄、核对——上百篇文献，动辄耗费科研人员数周时间。

SYS-03 // QUALITY BLACKBOX

质量黑盒不可信

拿到一行数据却无法回答：它被清洗过吗？依据是什么？多来源数值冲突时，该相信谁？缺乏可回溯凭证。

BENCHMARK & VERIFIED METRICS

全链路有据可查的工程与评测数据

所有数值均来源于公开测试代码、星表基准与已归档技术报告，拒绝未经实测的虚假包装。

521[1] 离线测试全绿
覆盖 AST 白名单沙箱、三路检索提取契约、LangGraph 状态机流转与六维质量雷达，全部使用 mock 离线环境隔离运行。
25[2] VizieR 星表
整合 CDS VizieR 权威天文数据库，涵盖 Gaia DR3/DR2、2MASS、WISE、SDSS、TIC、Hipparcos 等 25 组标准测光与光谱星表。
9[3] 智能体子图
解耦为意图澄清与规范化、检索与文献下载、多模态提取、质量评估、数据清洗、冲突裁决、人工复核、结构化导出与科研洞察 9 大 LangGraph 子图（subgraph1-3 + data_* 质量链）。
100[4] 类 otype 性质库
按天体类型（otype）组织的 RAG 性质库：100 类天体共 3,293 条性质定义（坐标、视差、距离、有效温度、金属丰度、年龄等），统一字段白名单与标准单位。
294[5] 条天体物理知识
沉淀 294 条天体物理先验知识（7 个主题：物理定律、参考值范围、天体模型、测量理论、研究方法、星系物理、瞬变源），支撑物理边界与合理范围校验。
6[6] 维质量评分
综合完整性、一致性、格式规范、来源可信度、冲突风险与提取质量 6 个量化维度（dimension_scores），加权输出雷达总分并提供留痕决策。

GET STARTED // 快速开始

四条命令，跑通全流程。

Python 3.10+ · 一句自然语言，走完检索、多模态图表提取、清洗与质检交付全生命周期。

STEP 01

克隆并安装

git clone https://github.com/lijiamingeric28-tech/AI-Scientist-2026.git cd AstroQuery_AI pip install -r requirements.txt
STEP 02

配置密钥

AstroQuery_AI/.env DASHSCOPE_API_KEY · DASHSCOPE_BASE_URL（必填）
ADS_API_TOKEN · UNPAYWALL_EMAIL（可选）
STEP 03

构建前端

cd frontend && npm install && npm run build 仓库不含预编译产物，启动 Web 界面前必须执行
STEP 04

发起查询

python -m astroquery_ai "M45 的年龄距离和金属丰度" 或 python -m web.desktop 打开轻量桌面窗口
AstroQuery_AI — shell
